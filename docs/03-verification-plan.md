# 냉각팬 제어 모델 검증 계획서

버전: v0.1 | 합의일: 2026-10-20

## 목적과 범위

모델이 REQ-001~011을 만족하는지 확인한다. 제어 출력, 상태, 시간 동작이 대상이다. 실제 하드웨어와 냉각 성능은 제외한다.

## 방법

| 방법 | 확인 내용 |
|---|---|
| 요구사항 리뷰 | 누락, 모순, 모호성, 검증 가능성 |
| 모델 정적 점검 | 자료형, 샘플 시간, 초기값, 연결, 오류 우선순위 |
| 동적 검증 | 정상·경계값·상태 유지·오류·복구·시간 조건 |
| 결함 주입 | 비교 연산, 상태 저장, 오류 우선순위 결함의 검출 |
| 회귀 테스트 | 수정 후 전체 테스트 재실행 |

수동 리뷰, 모델 설정 자동 검사, 도구 진단을 구분한다. 설정 자동 검사는 일반적인 정적 분석 또는 MISRA 검사를 대체하지 않는다.

## 테스트 설계 원칙

- TC-001~023을 독립 실행하며 매번 초기화한다.
- 입력과 기대 출력은 요구사항에서 도출해 사전 고정한다.
- 첫 입력은 t=0에 적용한다. 입력은 보간하지 않고 계단형으로 유지한다.
- 시간 테스트는 50ms에 입력을 바꾸고 100ms에 출력이 반영되는지 확인한다.
- 제어 주기보다 짧은 10ms 간격으로 관찰한다. 이 관찰 간격 미만의 변화는 직접 측정 범위 밖이다.
- REQ-001은 초기화 설정·상태 근거로 점검하고, t=0 출력만으로 증명하지 않는다.
- 센서 정상 상태에서 비유한 온도는 ASM-002 위반이므로 정상 동작 판정 대상에서 제외한다.

## 판정과 실행 기록

Boolean 출력은 기대값과 정확히 일치해야 한다. 시간은 10ms 관찰 인덱스에 맞춰 비교한다. 누락·중복 샘플, 잘못된 시간 및 Boolean이 아닌 결과도 실패로 처리한다.

MATLAB/Simulink·Python 버전, 소스 커밋 또는 작업 상태, 입력 버전, 실행 명령을 기록한다. 초기화 설정 점검, 테스트 통과율, 요구사항 검증 상태와 모델 구조 커버리지는 별도 항목으로 관리한다. 측정하지 않은 모델 커버리지는 수치화하지 않는다.

## 결함 관리

결함 ID, 요구사항·테스트 ID, 재현 입력과 버전, 기대·실제 결과, 원인, 수정, 재검증을 기록한다. 인위적 결함과 개발 중 발견한 결함을 구분한다.

## 완료 기준

- 모든 요구사항에 검증 방법과 근거 연결
- 계획한 점검 및 테스트 수행, 정상 모델 전체 동적 테스트 통과
- 발견 결함 수정·재검증 또는 미해결 사유와 영향 기록
- 결함 주입 후보별 검출 결과 기록
- 환경과 재실행 방법 문서화

사용 가능한 제품과 라이선스는 실제 환경에서 확인한다. ISO 26262 인증이나 MISRA 준수를 본 프로젝트의 결과로 주장하지 않는다.
